## Corrections de ce lot

- Le validateur JSON refuse les types ressemblants tels que application/jsonp, tout en acceptant application/json avec charset.
- Le limiteur local est plafonné à 10 000 compteurs. À saturation, les nouvelles clés sont refusées temporairement ; les compteurs actifs ne sont pas évincés. Expiration et reprise testées. Ce choix protège la mémoire mais peut réduire la disponibilité sous attaque ; une protection distribuée reste nécessaire.
- Les webhooks Stripe et Resend lisent au maximum 2 Mio réels, même sans Content-Length ou avec une longueur sous-déclarée. Le texte signé n'est ni parsé ni reformaté avant vérification. Stripe conserve son refus des signatures absentes et son traitement idempotent.
- Tests exécutant le vrai module de protection : MIME, taille réelle, origine, saturation/expiration et conservation du texte UTF-8 signé. La simulation de paiement existante couvre aussi le webhook Stripe signé et sa répétition sans réseau.

## Contrôles réalisés

- Audit pnpm --prod : aucune vulnérabilité connue signalée par le registre au moment du contrôle ; ne garantit pas l'absence de faille.
- Production : HEAD /api/admin/prospection sans connexion -> 401 ; Cache-Control private/no-store, HSTS, nosniff, DENY et noindex présents.
- Routes admin inspectées : contrôle serveur requireAdminUser ; mutations inspectées avec contrôle d'origine.
- Suppression de road trip et édition de fiche professionnelle : filtrage propriétaire présent dans les requêtes examinées.
- Photos de preuve : limite de taille, signature de fichier, stockage créé privé dans le code. État réel du bucket non vérifié.
- Git suit uniquement .env.example parmi les fichiers .env. Recherche ciblée de formats de clés privées dans src/public sans correspondance ; ce n'est pas un scan complet de l'historique ou des secrets de toutes formes.
